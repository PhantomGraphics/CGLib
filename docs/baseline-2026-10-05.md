### Finding: `CGLIB_BUILD_VIEWERS` is not consulted

The option is declared and printed in the configure summary only. Viewers are built whenever
Vulkan is ON, regardless of the option, which contradicts the standalone plan's "viewer gates are
implemented". Phantom's scenario runners depend on the viewers being built, so a fix must also
set the option in Phantom's top-level CMake. **Resolved 2026-10-05**: the five viewer targets are now gated by the option (default ON when top-level, Phantom forces ON); Vulkan ON + viewers OFF yields 0 viewer targets.

Observations relevant to later phases:
- `Renderer` depends on `VkAppBase` (via `IVkSubRenderer`, Phase 4 topic); `Animation`'s Vulkan
  parts depend on `GltfRenderer`, and `GltfRenderer` depends on `Animation` (core) - the module
  directory graph has a cycle that the `*Core` target split currently hides.
- `Scene/Scene/*Presenter.*` are excluded from `SceneCore` precisely because of the `Renderer`
  dependency; they are on-disk residue (Phase 6 candidate, verify usage first).
- Third-party headers: glm is included by almost every module's public headers (Math wraps it via
  relative path); Eigen only by `Numerics/Converter.h`; nlohmann only by AssetCore/SceneRuntime/
  GltfRenderer sources and headers; cgltf only in `File` sources; stb only in sources.

## Language standard, paths, exceptions

- CMake enforces C++20 for the whole library (`CMAKE_CXX_STANDARD 20`, `cxx_std_20` PUBLIC on
  every `*Core` as of 2026-10-05). The repository-root `CLAUDE.md` still says C++17 and
  `PhysicsCore` historically ran at C++17; both are stale/changed and should be reconciled in
  Phase 6.
- Headers are included as `"CGLib/<Module>/..."`; in the build tree this resolves through
  generated forwarding headers under `<build>/_cglib_headers/` (absolute source paths), in an
  install tree through `include/CGLib/` (same relative layout).
- Exceptions: no `throw` statements in non-ThirdParty, non-test library code. `try/catch` exists
  only at external boundaries (nlohmann/json parsing and filesystem calls in SceneRuntime and
  AssetCore, VRM parsing in GltfRenderer, `LightManager.h`, a few viewer panels). Public APIs
  report failure via `bool`/`std::optional`, per `CLAUDE.md`. `/EHsc` is required for these
  boundary catches to work (see `cmake/CGLibCommon.cmake`).
